## Context

An x402 `402` and the retry that answers it are one exchange, and only the party that issued the requirements can recognize the signature against them.

## Decision

The record, from ledger §B row D-109, verbatim:

> **The resource server holds the 402 state.** From the qisma study (G.5, Sonic: incorporate): a resource server that accepts only requirements it issued is stateful across the `402` and the retry; the WebMCP page is a client, the MCP server is the resource server; requirements are issued and recognized from one durable place. §14.2 MUST + T-P11-6.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

The MCP server is the resource server and holds the 402 state; the WebMCP page is a client of it and never the resource server. A Postmaster MUST accept a `PAYMENT-SIGNATURE` only against requirements it issued, and MUST issue and recognize them from one durable place — durable meaning surviving a restart (§14.2, T-P11-6). Taken from the qisma study as shape, with its in-memory replay sets named explicitly as what not to inherit.
