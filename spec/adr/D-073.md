## Context

D-55 put manifests on consensus before `send`, and the sender's outbound log is an HCS-10 topic with HCS-10's own semantics on it.

## Decision

The record, from ledger §B row D-73, verbatim:

> Manifest topic: every agent has one, created at provisioning, memo `wishmail:manifest:1`, sole submit key the agent's, declared as `manifestTopic` (HCS-11 `properties.wishmail.manifestTopic`, TXT `m=`, AgentFacts `wishmail.manifestTopic`). No WISHMail payload rides on an HCS-10 topic. A Verifier need not attribute a manifest: the AAD binds its hash. Supersedes D-55's "on the log".

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

Every agent gets a manifest topic of its own: memo `wishmail:manifest:1`, sole submit key the agent's, created at provisioning, declared as `manifestTopic` on every surface (§9.1, T-P17-3). Nothing but manifests goes on it and no HCS-10 topic carries a manifest. This is also what makes the return receipt attributable — a topic only the recipient's key can write to (§10.4, D-78).
