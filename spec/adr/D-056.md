## Context

Hashes were being described in the Ontologic notation h(R‖I‖O‖M), and a concatenation of four values has no single canonical byte sequence.

## Decision

The record, from ledger §B row D-56, verbatim:

> One hashing rule: SHA-256 over RFC 8785 canonical JSON; the AAD is a JWE-style protected header; base64url unpadded. RIOM's ‖ is notation.

## Alternatives considered

- Define a concatenation order and separator — rejected: it is a second serialization format to specify and test, where JSON canonicalization is already specified by an RFC.

## Consequences

One rule for the whole document: SHA-256 over the RFC 8785 canonical JSON of the object with the hash field absent. The AAD is a JWE-style protected header (RFC 7516 §5.1). Binary is base64url unpadded. ‖ is notation, not a construction (§5.1). Everything downstream — the AAD hash, proof hashes, the evidence digest — inherits this one rule.
