## Context

The UAID grammar had been written from memory and was wrong in a way that would have made every native address malformed.

## Decision

The record, from ledger §B row D-93, verbatim:

> **UAID grammar corrected**: HCS-14 at the pin defines `uaid:aid:{id};{params}` and `uaid:did:{id};{params}`; there is no `did:uaid`/`did:aid`. `nativeId` is CAIP-10 `hedera:<network>:0.0.N`; `uid` is the HCS-10 `operator_id` (`inboundTopicId@accountId`); parameter order `uid, registry, proto, nativeId, domain`. §2.2, §1.6, §9.1, §9.2 amended (`CHANGED`). Recon C-1.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

FETCHED at the pin: HCS-14 defines `uaid:aid:{id};{params}` and `uaid:did:{id};{params}`, parameters ordered `uid, registry, proto, nativeId, domain`. **There is no `did:uaid` and no `did:aid`.** `nativeId` is CAIP-10 `hedera:<network>:0.0.N`; `uid` is the HCS-10 `operator_id`, `inboundTopicId@accountId`. The AID hash is SHA-384 over canonical JSON of six fields, Base58 — which is what §9.5 recomputes for a `uaid:aid` address.
