# D-158 — The reference Correspondent watches its own doorbell and auto-accepts

Status:      accepted
Date:        2026-09-09
Decided by:  Sonic
Drafted by:  Claude Code
Sections:    none — §7.1 and §8.2 already fix what a lane is and that no answer is owed
Tests:       none added, moved or amended
Supersedes:  none
Spec marker: none

## Context

§8.2 is deliberate about this: "A recipient MAY leave a request unanswered
forever; nothing in this document obliges an answer." So the specification does
not say when a doorbell is answered, and it should not — that is a deployment's
policy. The reference implementation still has to do something, and until now it
had no rule.

The relevant fact is that the gate is already paid for. §4.4 puts a HIP-991 fee
of exactly one stamp on every doorbell, collected by the treasury before the
request lands; §17.3 grounds it: a mailbox "is not a public forum", and what the
fee secures is that only stamped mail reaches the door at all. A screening policy
on top of that is a second gate on traffic the first gate already priced.

## Decision

**While its process is up, the reference Correspondent reads its own inbound
topic and answers every `connection_request` that landed.** The one-stamp fee is
the gate, and it is the gate P-7 names.

Acceptance is §7.1's and nothing added to it: a connection topic whose submit
key is a threshold of exactly the two agents' keys (T-P17-2), carrying no custom
fee (T-P11-3), with its admin key set at creation per the acceptor's declared
policy (P-17); then `connection_created` on the acceptor's own doorbell with
HCS-10's memo (T-P9-5). The recipient's **agent signs** it; the recipient's
**operator pays** (D-156, D-157).

**Screening policies are 0.6** — an allow list, a higher fee, a human in the
loop. They are a class of thing, not one thing, and none of them is needed to
send the first letter.

**You cannot sign for a package if you aren't home.** An agent whose process is
down leaves the ringer with an attempted-delivery slip, and that is F-6 exactly:
silence is not refusal, expiry is not non-delivery, and the slip stays true of
the window it names even if the lane opens later (§8.2, §10.5). This goes in the
README beside the watcher, because it is the one place a reader is most likely
to mistake an absence for a rejection.

## Alternatives considered

- **Answer on an explicit `accept` call only.** Rejected for the demo: it makes
  the recipient's operator a party to every first contact in real time, which is
  precisely the coupling P-14 exists to forbid elsewhere and which no
  correspondence should need.
- **Screen by an allow list of accounts.** Deferred to 0.6, not rejected: it is
  a real policy and it belongs to a release that can state it in a claim.
- **Answer requests that arrived while the process was down, on restart.**
  Admitted by this decision and not required by it — the watcher reads the topic
  from the beginning, so a request that landed during a gap is answered when the
  process returns, and the slip its sender already holds stays true. §8.2 says
  so directly: "A lane that opens after the window was closed is OPEN, and the
  slip that was issued remains true of the time it describes."

## Consequences

No specification sentence changes. The reference Correspondent under `app/sdk/`
gains a doorbell watcher; `app/README.md` gains the sentence about not being
home. The watcher is a reference behaviour and no class is tested against it:
what the suite tests is the lane it creates (T-P17-2, T-P11-3, T-P9-5) and the
slip it fails to prevent (T-P12-5).
