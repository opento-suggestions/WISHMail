## Context

Rotation was being discussed as one thing when Hedera makes it two, and the difference decides what an agent loses when it rotates.

## Decision

The record, from ledger §B row D-65, verbatim:

> Rotation stated plainly: no sender key in the seal; recipients rotate encryption keys by epoch; Hedera account keys are literal on topics, so rotating one strands lanes keyed to the old key. Goes to §15.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

Encryption keys rotate by epoch, monotonically, every key retained so history stays readable (§7.6, P-8). Account keys are different: a topic's threshold key names account keys literally and does not follow an account whose key later changes, so a rotated account can still read every lane but can no longer sign on lanes created before the rotation. Stated as L-4 and F-8; new mail needs a new lane, born again from the doorbell.
