## Context

The most visible route to a Hedera agent registry is a broker — HOL, which aggregates sixteen registries. Depending on it would be a moat; ignoring it would be a pose. (The recon later measured how small the Hedera-native registries behind it actually are: `hol` 33 agents, `hashgraph-online` 359, `openconvai` 2, against 249,167 aggregated.)

## Decision

Incumbents are supported, never required. The HOL Registry is supported as one of several and P-4 holds regardless. "Require no moat; support every incumbent." RECORD.

## Alternatives considered

- Require the broker — rejected: P-4.
- Refuse to read it — rejected: an incumbent an agent actually uses is an address that has to resolve.

## Consequences

Becomes P-5 and §3.4. The disposition this ADR left open — the profile "deferred, likely one-of-multiple", appraised as a downgrade — was replaced: D-103 removed the broker API from the pins, and D-104 re-founded `hol` on the consensus anchors with the broker as a directory and nothing it says an input. §9.5 is that rule, and the endorsement is `blurred`, not `withheld`.
