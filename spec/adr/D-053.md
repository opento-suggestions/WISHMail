## Context

D-1 put the resolution proof inside the AAD and D-26 reduced it to a hash. What the AAD contains, and what its hash is for, still had to be fixed exactly.

## Decision

The record, from ledger §B row D-53, verbatim:

> AAD = hash(ledgerTag ‖ lane ‖ resolutionProofHash ‖ nonce); the settlement memo carries the AAD hash; the AAD hash is the envelope identifier. P-1's text changes.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

The AAD names the lane, the resolution proof, and a fresh nonce; the settlement's memo carries the AAD hash; the AAD hash is the envelope identifier. P-1's text changes to this. **Two later corrections**: the ‖ concatenation this row writes is notation only — D-56 makes the construction canonical JSON — and the key names were fixed to `{p, v, l, lane, rp, nc}` by D-127, which matters because under RFC 8785 different key names are different bytes.
