## Context

A Verifier's reading could be published on consensus under its own key, which would make a reconciled state a fact and give the state machine something after ACKED.

## Decision

The record, from ledger §B row D-68, verbatim:

> Design, not BUILD: `attest` — a seventh verb by which a VERIFIER emits its reading to consensus under its own account, making a reconciled state a fact (the state after ACKED). Trust class math (rule = `verify` at a version; inputs = scope + window; output = bundle digest; replayable by anyone); attribution by the Verifier's account (fourth weld); the competitive tier's product (D-31). §16.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

`attest` is design, not build: §16.2 fixes its shape so a later release can implement it without redesigning the core, and §8.3 records that there is no state after ACKED at this version. What it may never do is add standing — an attestation is one Verifier's reading, replayable by any other, and a Postmaster MUST NOT publish one (T-P2-3, extension).
