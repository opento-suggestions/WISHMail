## Context

HCS-10 delegates anything over its size line to HCS-1. Following that would put envelope content in a file topic addressed by an HRL, outside the lane.

## Decision

The record, from ledger §B row D-46, verbatim:

> Envelope chunking is app-level inside HCS-10 `message` ops on the lane; HCS-1/HRL not used for content (reverses Q-4's 08-10 closure). HCS-1 stays pinned for HCS-11 profile storage.

## Alternatives considered

- HCS-1 for envelope bodies, as HCS-10 suggests — rejected: an envelope must live on the lane, so that reconstruction reads one topic and the chain binds what it finds there (§2.3, §7.4).

## Consequences

Chunking is app-level inside HCS-10 `message` operations. HCS-1 stays pinned, but for reading HCS-11 profiles (§9.2), never for content. Reverses the 2026-08-10 closure of Q-4. The size line this implies was fixed by D-62 and corrected by D-96.
