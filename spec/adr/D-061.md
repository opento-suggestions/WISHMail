## Context

Sealing needed a construction that binds the AAD, needs no long-term sender key, and has test vectors somebody else wrote.

## Decision

The record, from ledger §B row D-61, verbatim:

> Sealing is HPKE base mode, DHKEM(X25519, HKDF-SHA256) / HKDF-SHA256 / AES-256-GCM, single-shot, info `wishmail/0.4/seal`, AAD = §7.2 bytes.

## Alternatives considered

- A bespoke encrypt-then-MAC construction — rejected: no external vectors, and the AAD binding would be ours to get right alone.

## Consequences

HPKE (RFC 9180) base mode, single-shot, DHKEM(X25519, HKDF-SHA256) / HKDF-SHA256 / AES-256-GCM. Base mode means a fresh ephemeral key per envelope, so a Correspondent has no encryption key to rotate and the sender is identified by the fourth weld instead (§7.2, §7.3). **The `info` string this row gives as `wishmail/0.4/seal` moved to `wishmail/0.5/seal` at the freeze** (D-125); it is a wire string, so the move was a minor version.
