## Context

The profile had been drafted against AgentFacts documents, and the recon found the live index serves something else entirely.

## Decision

The record, from ledger §B row D-97, verbatim:

> **The `nanda` profile is the NANDA v2 index, not an AgentFacts document.** From the NANDA recon (09-06): there is no `ans://`; the live index parses `urn:ai:domain:<d>[:agent:<slug>]` / `urn:ai:email:<e>` (`locatorParser.ts:23-31`); the v2 index does not serve AgentFacts (chain ends at an A2A card); list39 strips extension fields on read (`public.js:26-43`); AgentFacts is unsigned, no key, not JSON-LD; the index dropped its signature and audit-log tables (migration 003); `metadata`/`data` are `additionalProperties: true` with an observed `org.projectnanda.*` reverse-DNS key convention. Profile renamed `agentfacts` → `nanda`; address `nanda:<urn>@<index-host>`; rule reads `/api/v1/resolve` (not `/api/ard/*`) and takes the declaration from `index_record.metadata["org.wishmail"]` or `["org.wishmail.agents"][slug]`; `blurred` always; trust class social-committee decisively. §2.2, §3.4, §9.1, §9.4, T-P12-6 amended (`CHANGED`). Keying by org vs agent slug and the choice to drop the `https://` document address are MINE (G.4).

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

FETCHED 2026-09-06: there is no `ans://` anywhere; the live v2 index parses `urn:ai:domain:<d>[:agent:<slug>]` and `urn:ai:email:<e>`; AgentFacts survives only in v1 and list39, with zero AgentFacts references in v2 source. The profile is renamed `nanda` and keyed to the NANDA v2 index. This is why §9.4 speaks `/api/v1/*` and not the `/api/ard/*` mirror, which is a different wire format and not interchangeable.
