## Context

A Verifier that must implement every profile could not exist without a DNS resolver and an HTTPS client, which would put a network dependency under P-4.

## Decision

The record, from ledger §B row D-75, verbatim:

> The VERIFIER floor stays profile-less (§1.4 governs): a Verifier MUST replay every profile it claims, SHOULD replay `hcs14`, and with no profile verifies binding, settlement, and postmarks and appraises every resolution unverified. §9.6's first draft made `hcs14` a MUST, which would have required a registry of a class (P-5) and contradicted §1.4.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

The floor stays profile-less: a Verifier MUST replay every profile it claims, SHOULD replay `hcs14`, and one claiming none still verifies binding, settlement and postmarks and appraises every resolution unverified — and is conforming (§9.6, T-P12-4). A downgrade, never an error, which is P-12.
