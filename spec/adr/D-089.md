## Context

Schemas registered under HCS-13 are immutable once registered, and a patch release that changed one would silently change what a conforming release does.

## Decision

The record, from ledger §B row D-89, verbatim:

> Versioning is `major.minor.patch`. Wire strings (AAD `v`, HPKE `info`, `schemaRef`) and HCS-13-registered schemas carry `major.minor`; a patch revision amends text and tests and may change neither a wire string nor a schema already registered for its minor version (v0.4.1's chunk change is legal only because nothing is registered yet); a change that would is a new minor version. §1.7 amended (`CHANGED`); T-P9-9. Sonic's rule, with the post-registration edge stated by Claude.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

`major.minor.patch`, independent of any implementation. The wire carries `major.minor` and nothing finer — the AAD's `v`, the HPKE `info`, the `schemaRef`'s registered version. A patch amends text and tests and may change neither a wire string nor a registered schema; a change that would do either is a new minor version (§1.7, T-P9-9).
