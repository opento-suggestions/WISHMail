# D-147 — The provisioning template gains the declaration registry topic

Status:      accepted
Date:        2026-09-08
Decided by:  Sonic
Drafted by:  Claude Code
Sections:    §9.2, §4.6 (no sentence changes; the policy is already stated there)
Tests:       T-P17-1 — not amended; §9.2:1284 already names the registry topic under it
Supersedes:  D-138's provisioning template (the four-row table; its four rows are unchanged)
Superseded:  none
Spec marker: none — no specification sentence changes

## Context

D-138 carries the key policy for every topic WISHMail provisions, as a table, stated once, because the reference Postmaster provisions its own agent by the customer path and so that table is the template every provisioned agent inherits. It has four rows: doorbell, log, manifest, lane.

§9.2 names a fifth topic type it does not list. `spec/WISHMAIL_SPEC_v0_5.md:1283`:

> An agent declaring under `hcs14` MUST set its account memo to `hcs-11:hcs://2/<registryTopic>` where the registry is an HCS-2 topic it controls, register each profile version there, and carry `properties.wishmail` in the profile. Rotation is a new profile file registered as a new entry; prior entries stay on the registry topic.

and `:1284` puts it under the same test as the rest:

> `Conformance:` … T-P17-1 — the declaring fixture's registry topic has the agent's key as its sole submit key.

§4.6:578 confirms the Postmaster creates it on the provisioned path: "the Postmaster pays to create the account, the doorbell, the log, the manifest topic, and — under the native profile — the declaration registry and profile file, with those keys as their owners."

So nothing was undecided. What was missing was the row, in the one place the policy lives. P-17's own text at `:1699` enumerates only the lane, the manifest and the admin-key rule, so the table is where the full policy would be found or not found at all.

Raised as ledger §G item 11 (Claude Code, 2026-09-07, MINE), noted as not blocking the entity phase — the declaration is downstream of the entities — but as something the table should carry before a customer agent is provisioned.

## Decision

**The provisioning template is five rows** (RECORD, Sonic 2026-09-08). D-138's four rows are unchanged; a fifth is added.

| Topic | Memo | Submit key | Admin key | Fee schedule key | Fee | Exempt list | Warrant |
|---|---|---|---|---|---|---|---|
| doorbell (HCS-10 inbound) | `hcs-10:0:60:0:<agentAccount>` | **none** | agent | **none** | HIP-991, 1 `$POSTAGE`, collector = treasury | the agent's own key | `index.md:113`, §4.4, D-137 |
| log (HCS-10 outbound) | `hcs-10:0:60:1` | agent | agent | — | none | — | `index.md:114` |
| manifest | `wishmail:manifest:1` | agent (sole) | agent | — | none | — | §9.1:1253 |
| declaration registry (HCS-2) | `hcs-2:0:<ttl>` | agent (sole) | agent | — | none | — | §9.2:1283-1284 |
| lane (HCS-10 connection) | HCS-10's connection memo | threshold of the two agents' keys | per acceptor's policy | — | none | — | §7.1:984 |

This supersedes D-138's table specifically, not D-138. Its reasoning stands in full, including its warrant for the doorbell carrying **no fee schedule key** — the fee is immutable at birth, P-17's doctrine and §4.4's "exactly one stamp" made structural, and HIP-991 `:97` makes the omission one-way. **This decision does not touch that row.**

### The registry topic's own row

Sole submit key the agent's, which is what `:1284` tests. Admin key the agent's, by §4.6:583's MUST and D-146. No fee: the registry is the agent's own publication surface, not a doorbell, and nothing rings it. No fee schedule key, for the same reason there is no fee.

**MINE — the memo's `indexed` flag is `0`.** Ledger §H gives HCS-2's registry memo as `hcs-2:[indexed]:[ttl]`, where indexed 0 means read all messages and 1 means the last message is the state. §9.2:1283's "Rotation is a new profile file registered as a new entry; prior entries stay on the registry topic" wants prior entries readable at their own consensus timestamps, which is what T-P8-3 tests — "after a fixture recipient rotates, the coordinates declared before rotation are still resolvable at their consensus timestamp". Indexed 1 would not give that. The TTL is a deployment fact of the same kind as D-138's `60`, recorded in the ops record with its source and not in the specification.

### What this decision does not do

The row lands so the template is complete before any customer agent is provisioned. **It does not pull the declaration into the entity phase.** Creating the registry topic is one of four steps — the topic, the HCS-11 profile inscribed as an HCS-1 file, the HCS-2 `register` entry naming it, and an `AccountUpdateTransaction` setting the memo — and STATUS §3 puts that after the entities. The entity phase creates the Postmaster-agent's doorbell, log and manifest, and no registry topic; `.env.example` gains no new name in that window.

## Alternatives considered

- **Add the row when the declaration is actually built.** Rejected: the table is what every provisioned agent inherits, and a template known to be incomplete is a template that provisions incompletely the first time someone uses it.
- **Provision the full declaration in the entity phase.** Rejected as scope: it pulls HCS-1 inscription (brotli, base64, chunked, digest-in-memo) and the account-memo update forward, and the account memo is the one destructive write in provisioning — §9.2 records that a memo's past values are not re-obtainable.
- **State the policy in §9.2 instead of the table.** Rejected: §9.2 already states it. Restating a normative sentence in an ADR is not a decision, and duplicating it in the specification would carry a `CHANGED` marker for no change.

## Consequences

`spec/adr/D-138.md` gains `Superseded: provisioning template by D-147` and keeps its text, per the reciprocal convention in `spec/adr/TEMPLATE.md`. The pointer is on the table, not on the decision: D-138's rulings about the doorbell's keys, the absent fee schedule key and the TTL are unaffected.

No specification sentence changes, so no `CHANGED` marker and no §18.2 row — §18.2's stated criterion is whether a decision shaped the document's text, and this one did not. No test is added or removed; the register stays 83.

Ledger §G item 11 is closed. Nothing is deferred: rotation and the exempt list are covered by the admin key each topic already carries.
