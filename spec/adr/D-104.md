## Context

An agent registered through the HOL broker is on consensus, and the broker's own answer about that agent is not. Which of the two a resolution reads decides whether `hol` is `math` or hearsay.

## Decision

The record, from ledger §B row D-104, verbatim:

> **`hol` profile reads consensus; the broker is a directory.** Approved 09-06 with forks closed: no social-committee fallback for unanchored agents (a database row is not evidence); `blurred` is the endorsement for "on consensus, under someone else's key" — Sonic: it suits the Sorensen-based statusProfile shape (vague, missing, blurry, faint); T-P6-5's fixture pins the profile→canonical mapping for the AID recompute (name ← `alias`/`display_name`, version ← `version`, skills ← `aiAgent.capabilities`; `registry`/`proto`/`nativeId` from the address).

## Alternatives considered

- A social-committee fallback for agents the broker lists but the ledger does not — rejected: a database row is not evidence, and an agent the ledger does not carry is unresolvable under this profile.

## Consequences

`hol` reads the consensus anchors: a `register` operation naming the agent, then the HCS-2 topic or the account memo, then the HCS-1 file, then the HCS-11 profile — a chain the recon verified end to end from a mirror node with no broker. Trust class `math`. `blurred` is the endorsement for 'on consensus, under someone else's key', which is what a broker-submitted registration is (§9.5, T-P6-5, L-8).
