## Context

An undefined ledger tag was refused only by an extension, which left a core Postmaster untested on carrying one and §11.5 with no row for it.

## Decision

The record, from ledger §B row D-113, verbatim:

> **The undefined-ledger-tag MUST moves to the core (§5.1); T-P9-11 is a core test.** Sonic 09-06: agreed. As an extension test it bound only a claiming release, leaving a core Postmaster untested on carrying `hdr.l = <unknown>` and §11.5 with no row for it. Now: `send` rejects, a Verifier appraises unbound (a binding failure — the AAD names a lane on a ledger the chunks are not on — hence unbound, not unverified; P-12 satisfied as the lowest standing). §11.5 gains the row `ledger tag defined here or by a claimed extension → unbound → T-P9-11` (`CHANGED`); §16.7 keeps its prose and no MUST; P-9's text and stated-in updated (`CHANGED`).

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

The MUST moves to the core §5.1 and **T-P9-11 becomes a core test**: an envelope whose AAD names a tag neither this document nor a claimed extension defines is rejected at `send` and appraises unbound at replay. As an extension test it bound only a claiming release, which is exactly backwards for a refusal.
