## Context

An envelope's header names the epoch it sealed against, and nothing stopped that from disagreeing with the epoch the bound resolution yielded.

## Decision

The record, from ledger §B row D-83, verbatim:

> Header `ke` ≠ the bound resolution's `keyEpoch` ⇒ unbound (T-P1-10). Under §6.4's order (manifest, then assembly; TTL re-resolve before assembly) there is no legitimate path to a mismatch.

## Alternatives considered

- None recorded. The ledger §B row states the decision without a fork; where a fork was closed, the row says so.

## Consequences

`hdr.ke` MUST equal the coordinates' `keyEpoch`; an envelope for which it does not is unbound and MUST NOT be opened (§11.4, T-P1-10). Under §6.4's order — manifest, then assembly, with a TTL re-resolve before assembly — there is no legitimate path to a mismatch, so the check costs a conforming sender nothing and closes a substitution to everyone else.
