# D-33 — A multi-profile `resolve` returns a set; the sender chooses and declares

## Context

An address may be resolvable under more than one profile, and something has to decide which resolution the envelope binds.

## Decision

As carried: `resolve` returns a set of resolutions across supported profiles; the sender chooses one and declares it; the reference implementation has a baseline default and is configurable. RECORD, 2026-09-04.

## Alternatives considered

- Resolve under one profile only, chosen by the caller — this is what 0.5.0 does.

## Consequences

CARRIED IN PART. §6.2 fixes the signature as `resolve(address, profile?) -> MailCoordinates`: one profile, one set of coordinates, one resolution proof. What survives of this decision is its substance — the sender chooses the profile and the envelope declares it (§7.2's `rp`, the chunk header's `pr`), and a multi-profile implementation is a caller calling `resolve` once per profile. What does not survive is the set-valued return.

The divergence between this carried decision and §6.2 was raised at the ADR backfill of 2026-09-07 and ruled the same day: **D-133** — one profile, one resolution, one delivery, one message send, one proof. §6.2 is confirmed as written; the choice happens before the proof is made, because by assembly the proof's manifest is published and its hash is what the AAD commits.
