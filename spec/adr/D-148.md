# D-148 — `$POSTAGE` is pre-minted 10,000 to the treasury, and the supply key is the treasury's

Status:      accepted
Date:        2026-09-08
Decided by:  Sonic
Drafted by:  Claude Code
Sections:    §4.1, §4.3, §4.4, §3.5 (no sentence changes; parameters §4.1 leaves open)
Tests:       T-P7-4 — not amended; this is what lets its charged half be shown positively
Supersedes:  D-141's `initialSupply: 0` and its operator-held supply key
Superseded:  none
Spec marker: none — a deployment fact; no specification sentence changes and no schema changes

## Context

D-141 fixed `$POSTAGE`'s parameters: `decimals: 0` (forced, because a HIP-991 fixed fee is written in base units and §4.4's "exactly one stamp" is one unit only at zero decimals), `supplyType: INFINITE`, a supply key and no other key, and `initialSupply: 0` with minting on demand — on the reasoning that §4.3 permits burning and L-12 says this release burns nothing, so supply grows, and "a pre-mint invents a number."

Designing the HIP-991 probe showed what a zero supply costs. T-P7-4 has two halves:

> Every fixture doorbell carries a HIP-991 custom fee of exactly one unit of the pinned stamp token with the **treasury** as collector; a fee-less connection request is rejected at the network; … and an owner's `connection_created` on its own doorbell assesses the owner zero stamps.

The exempt half is demonstrable with no supply at all — a signature on the exempt list waives the fee, so nothing needs paying. The charged half is not. With `initialSupply: 0` the only path to a stamp is `buy_stamp`, which belongs to a later phase, so no account on testnet can hold one, and the most the probe could show is a stranger **failing** for want of a stamp. A negative demonstration proves the fee exists; it does not show that the network assesses one stamp to the treasury, which is the sentence §4.4 actually makes and the property the doorbell path depends on.

## Decision

**`initialSupply: 10000`, minted to the treasury at creation, and `supplyKey` = the treasury's key** (RECORD, Sonic 2026-09-08).

Everything else in D-141 stands unchanged and for its own reasons: `decimals: 0`, `supplyType: INFINITE`, and the six absent keys — **no admin, freeze, wipe, pause, KYC or fee-schedule key** — with the refusal still checkable as six nulls on the mirror node, and the tail still stated rather than hedged: with no admin key the treasury can never be changed, so loss of the treasury key is terminal and this BUILD accepts a rebuild as the remedy.

### What the pre-mint buys

A positive test. With 10,000 units in the treasury, the probe creates a scratch stranger account, associates it, transfers it one stamp from the treasury, and has it submit to a fee-gated topic. The mirror node's `assessed_custom_fees` then shows amount 1, `token_id` `$POSTAGE`, collector the treasury — §4.4's sentence, observed rather than inferred, before the real doorbell is created.

10,000 is a working float, not a supply cap: `INFINITE` is unchanged, minting on demand is unchanged, and §4.3's burn remains permitted and unused (L-12). The number is a deployment quantity and lives in the ops record, not in the specification.

### Why the supply key moves to the treasury

The supply lands in the treasury, and the treasury's key is already hot — §14.2's purchase is atomic, so it signs the stamp leg of every `buy_stamp`. One key for one job. The alternative had the operator holding minting authority over a balance it does not hold and cannot spend, which is a split with no containment value: an attacker with the operator key could mint into the treasury but not move what it minted, and an attacker with the treasury key could already drain the float. D-140's split is containment and accounting, and this keeps it exactly where it was.

P-13 is untouched. This is the organization's own token and the organization's own keys; no agent's key is held by anyone but the agent.

## Alternatives considered

- **Keep `initialSupply: 0` and demonstrate the charged path negatively.** Rejected: it leaves T-P7-4's second half undemonstrated until `buy_stamp` exists, and the doorbell is created before then.
- **Mint on demand inside the probe, with an operator-held supply key.** MINE, rejected: it works, but it makes the probe's result depend on a mint the probe itself performs, and it keeps the split whose only effect is that two keys are needed to do one thing.
- **Pre-mint a larger float.** Rejected: 10,000 covers the probe, the T-P7-4 fixture and early `buy_stamp` traffic on testnet; a bigger number would say something about expected volume that nothing knows yet.
- **Give the token an admin key so the treasury could be changed later.** Not reopened — D-141 settled it: an admin key lets the Postmaster mutate the token a Verifier measures against (P-2) and destroys replay's fixed point.

## Consequences

`spec/adr/D-141.md` gains `Superseded: initialSupply and the supply key by D-148` and keeps its text; the reasoning that was overtaken is the part a reader needs.

The token's readback asserts `initial_supply == 10000`, `total_supply == 10000` and `supply_key.key` equal to the treasury's raw hex, beside D-141's unchanged six nulls and `treasury_account_id`, `decimals == 0` and `supply_type === 'INFINITE'`.

**No schema changes.** `$POSTAGE`'s parameters are named in no schema — `spec/pins.json` records `{tokenId, treasury}` for the stamp token and nothing about supply — so this decision touches `spec/schemas/` not at all, which the Phase A′ gate confirms as a separate item.

The probe's charged path becomes positive, and the scratch stranger it funds is recorded as `probe.stranger` and not deleted: a token balance blocks `AccountDelete`, and the T-P7-4 fixture can reuse it.
